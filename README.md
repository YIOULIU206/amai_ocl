# AiMai OCL

`aimai_ocl` is a research codebase for studying Organizational Control Layers
(OCLs) in multi-agent economic systems.

The repository explores how an explicit control layer can improve reliability,
constraint satisfaction, and decision quality in language-agent workflows. The
current setting uses AgenticPay as an external negotiation substrate and adds a
control plane for role decomposition, risk gating, auditability, escalation,
and attribution.

## Overview

This repository focuses on three questions:

- How should raw language actions be mapped into executable economic actions?
- When should a system approve, rewrite, block, or escalate an agent action?
- How can platform-side control be evaluated under partial observability and
  multi-turn interaction?

The current public codebase includes:

- an OCL implementation in [`aimai_ocl`](aimai_ocl)
- a ToolGuard-Commerce external baseline in
  [`aimai_ocl/baselines/toolguard_commerce`](aimai_ocl/baselines/toolguard_commerce)
- experiment scripts in [`scripts`](scripts)
- a local benchmark module in
  [`benchmarks/conversational_consumer_selection_v2`](benchmarks/conversational_consumer_selection_v2)
- tests in [`tests`](tests)

## Main Components

- `Role decomposition`
  separates planning, execution, and escalation responsibilities
- `Risk gating`
  scores candidate actions and chooses approve, rewrite, block, or escalate
- `Audit traces`
  records structured control decisions for later analysis
- `Escalation and replanning`
  handles infeasible or high-risk actions
- `Attribution`
  supports post-hoc contribution analysis across algorithmic components
- `ToolGuard-Commerce baseline`
  provides a matched external guardrail between seller generation and
  environment execution for comparison with OCL

## Research Setting

The repository currently uses two benchmark layers and one external control
baseline:

- `AgenticPay`
  is treated as an external negotiation/runtime substrate
- `Conversational Consumer Selection V2`
  is a local benchmark for controlled guided selection and dual-agent
  transaction dialogue under incomplete buyer intent
- `ToolGuard-Commerce`
  adapts the pinned
  [IBM ToolGuard](https://github.com/IBM/tool_guard) implementation to the
  commerce action boundary as a deliberately narrower comparison with OCL

### ToolGuard-Commerce baseline

The `toolguard_commerce` experiment arm checks each seller proposal after the
seller LLM produces it and before it reaches `env.step()`. Its behavior is
intentionally limited:

- the guard can only allow or block; it does not rewrite, clamp, or escalate
- a blocked proposal may be regenerated by the same seller LLM once by default
- if the retry still violates policy, the round becomes a no-op
- the guard can use the platform-visible buyer budget, but that value is
  removed from seller observations and retry feedback
- missing, unloadable, or lookup-dependent generated guards fail closed
- deterministic proposal IDs connect proposals, guard decisions, retries, and
  environment execution in the event log

The matched-context comparison arm, `ocl_matched_context`, gives OCL the same
observation-only seller context used by `toolguard_commerce`.

The benchmark module is documented in
[`benchmarks/conversational_consumer_selection_v2/README.md`](benchmarks/conversational_consumer_selection_v2/README.md).
It preserves the original guided-selection interface:

- input: `Observation`
- output: `SelectionAction`

and also adds a transaction dialogue layer where buyer and seller/clerk LLMs
exchange visible messages while hidden `ENV_ACTION` tags are stripped before
the other agent sees them and recorded in an environment event log.

The benchmark core does not instantiate OCL. OCL, prompt-policy, judge-review,
and ablation arms belong in an integration layer that wraps the benchmark's
parsed actions and event log.

The benchmark supports four visibility regimes:

- `v0_structured`
- `v2_direct_intent`
- `v2_partial_intent`
- `v2_hidden_intent`

## Installation

Create a Python environment and install the project:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
```

Install AgenticPay separately as an external dependency:

```bash
pip install "git+https://github.com/SafeRL-Lab/AgenticPay.git"
```

If you want to run the guided-selection benchmark as a package, also install:

```bash
pip install -e benchmarks/conversational_consumer_selection_v2
```

ToolGuard-Commerce is optional. Install its pinned dependencies with:

```bash
pip install -e ".[toolguard]"
```

For OpenAI-backed runs, set:

```bash
export OPENAI_API_KEY=...
export OPENAI_MODEL=gpt-5.4-mini
```

## Quick Start

Run one negotiation episode:

```bash
python scripts/run_demo.py --arm ocl_full --model gpt-5.4-mini --seed 42
```

Run a paired batch evaluation:

```bash
python scripts/run_batch_eval.py \
  --arms single,ocl_full \
  --episodes-per-arm 20 \
  --seed-base 42 \
  --output-dir outputs/main_result_v2
```

Run a `tau` sweep over control strength:

```bash
python scripts/run_tau_sweep.py \
  --tau-values 0.0,0.25,0.5,0.75,1.0 \
  --episodes-per-arm 20 \
  --seed-base 42 \
  --output-root outputs/tau_sweep_v2
```

Run the guided-selection benchmark demo:

```bash
cd benchmarks/conversational_consumer_selection_v2
PYTHONPATH=src python -m conversational_consumer_selection.clerk_agent_demo --backend demo
```

### Run the ToolGuard-Commerce comparison

ToolGuard generates executable guards from the included seller policy and tool
definition. First verify the readable YAML mirror and inspect the build
requirements:

```bash
python scripts/build_toolguard_commerce.py --verify-mirror
python scripts/build_toolguard_commerce.py --check-env
```

Set the model used by ToolGuard's second generation step, then build the
guards. Both generation steps require model credentials:

```bash
export TOOLGUARD_STEP2_GENAI_MODEL=gpt-4o-2024-08-06

python scripts/build_toolguard_commerce.py \
  --out-dir artifacts/toolguard_commerce \
  --step1-model gpt-4o-2024-08-06 \
  --step1-provider openai
```

Verify the generated step-2 guards before starting an experiment:

```bash
python scripts/build_toolguard_commerce.py \
  --preflight \
  --out-dir artifacts/toolguard_commerce/step2
```

Run the adversarial-buyer benchmark across simple baselines,
ToolGuard-Commerce, matched-context OCL, and full OCL:

```bash
python -m aimai_ocl run configs/benchmark_baselines_toolguard.yaml \
  --episodes 20 \
  --output-dir outputs/toolguard_comparison
```

Use `--dry-run` to inspect the resolved experiment plan without loading guards
or calling a model.

The output records ToolGuard-specific counts and rates, including proposals,
detections, blocks, interceptions, retry attempts, successful revisions,
retry exhaustion, actions reaching the environment, and guard runtime.
